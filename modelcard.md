## Reflection: 
The first limitation is more categories than songs. The system recommendations are only limited to the amount of songs in that csv file. The second limitation is that if a song is not recognized in the smiltarity table, it is treated as distant and will recieve little credit in genres which can underepresent songs. The AI can be misused by overpersonalizing the content. What this would do, it can exlude other tastes and genres by repeatedly pushing the same genre or mood despite user input changes. To prevent this, the system should be transparent and say how the recommendations are generated and include guardrails for inputs that don't match for the user. A reliability system should also help with this. I was surprised me while testing the reliability of AI was how sensitive is was with edge cases. For example when I changed the mood from happy to sad after using happy a few times, even during then, it still gave me mostly happy songs despite the genre change. It showed me that even the recommendations with a reliability system and test, it still was sensitive to sudden changes from the user. I used AI in this project with code cleanups and annotating as well as suggestions on generating the reliability system, cleaning up errors and questions as well as helping me turn the code into a more testable AI system. One flawed suggestion it gave me was that it suggested a way to reccomend songs which would heavily underepresent songs and treat some songs as completely distant if it did not fit only 1 or 2 moods or genres.
